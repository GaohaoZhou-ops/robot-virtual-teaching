## 缓存、目录与恢复

地图示教与独立示教使用各自的工作缓存、目录权限和恢复副本。切换模式先保存当前现场，刷新后恢复最后激活的模式。

| 保存方式 | 包含内容 / 使用方式 |
| --- | --- |
| 浏览器自动保存 | 点云缓存、机器人与关节、示教任务、导航图、视角与显示设置 |
| 完整工程目录 | 地图、机器人、视觉资源与配置；支持按变更增量写入 |
| 兼容 JSON 工程配置 | 旧版配置导入，不能替代携带完整资源的工程备份 |
| 完整 ZIP | 便携工程备份；跨设备解压后可作为工程目录打开 |
| 服务重启保护副本 | 重启后在“加载工程”或“示教数据”中恢复 |

加载顺序：**默认工程目录 → 本地自动保存工作区 → 服务重启保护副本**。也可选择其他目录，或通过“加载工程引导文件”导入 JSON / ZIP。

> **目录写入条件**：Chrome / Edge 在 `localhost` 或 HTTPS 下可授予读写权限。普通局域网 HTTP 或不支持该 API 的浏览器会回退为只读目录，当前工作仍受浏览器缓存保护。

| 底栏状态 | 含义 |
| --- | --- |
| `SESSION AUTO-SAVE` | 浏览器自动保护正常 |
| `PROJECT SAVING` | 正在写入工程目录 |
| `PROJECT SYNCED` | 工程目录已完成增量保存 |
| `PROJECT READ ONLY` | 目录只读，无法直接增量写入 |
| `RECOVERY READY` | 存在可恢复的未完成工程 |

## 工程导出与示教数据导出

地图示教和独立示教都提供完整工程保存入口，一次保存会包含当前工作区、另一侧已打开的工作区，以及独立示教列表中的全部历史组。

**另存为工程、保存工程和导出工程** 同时打包真机孪生的机器人卡片，包括名称、地址和端口、颜色及多选状态。加载后即可在“同步作业 → 真机孪生”中使用这些卡片，无需重新填写地址。导入按地址合并，保留本机其他机器人；旧工程没有连接配置时保持本机卡片不变。管理员密码、鉴权令牌、连接会话和实时数据不打包，新设备首次连接时填写密码；本机已有同地址卡片仍可沿用其已记住的密码。加载工程只恢复配置，点击“连接并同步”后才访问机器人。

| 入口 | 文件 | 保存内容与用途 |
| --- | --- | --- |
| 工作台 **工程 → 另存为工程**，或示教数据页顶部的 **导出工程** | 默认 `atlas-project-<map\|independent>-<时间>.zip`，保存时可重命名 | 地图 / 物体、各组机器人模型与依赖文件、预设姿态、路径、全部示教任务与独立示教缓存、RGB / 点云、视角及转换关系；可在其他设备直接加载 ZIP 恢复 |
| 工作台 **工程 → 保存工程** | 最近一次成功另存为的 ZIP 文件 | 用当前工程内容覆盖该文件，无需再次选择位置；尚未另存为时不可用 |
| 地图示教数据树的 **导出示教数据** | `robot-teaching-*.zip` | 导出任务、停车点、Pose、对应机器人的预设姿态和完整路网，由机器人现有 v23 导入器一并恢复 |
| 独立示教数据树的 **导出示教数据** | `atlas-teaching-independent-<时间>.json`，或绑定地图并同步路网后选择 `robot-teaching-*.zip` | JSON 保留独立模型坐标下的机器人定位、关节值、停车点、Pose、关节姿态库与导航关系；ZIP 按绑定矩阵转换当前独立示教任务，并携带地图路网 |

独立示教同时具有有效地图绑定关系、可用地图路网并已开启路网同步时，点击“导出示教数据”会弹窗提供“地图示教任务 ZIP”和“独立示教任务 JSON”。ZIP 使用当前独立示教的最新任务快照，转换到地图坐标后进入现有机器人导出校验窗口，不包含地图侧其他示教任务，也不切换工作区、放置模型或修改任一侧缓存。不满足上述条件时继续直接下载原有 JSON；地图视角的导出流程不变。

独立示教导出验证：`npm run test:independent-export`；界面分流、格式选择、下载内容及缓存保护：`tests/independent_teaching_export_ui_smoke.py`（使用隔离浏览器和开发服务）。

示教数据树工具栏根据选中节点切换操作：选中任务显示“导出示教数据”；选中停车点显示“复制停车点”；选中姿态显示“复制姿态”。复制写入剪贴板，成功或失败会显示提示。

- **复制姿态**采用 `pre-teaching-pose.json` 格式：仅含 `unit: "deg"` 和 `joints`，四组为 `head`（yaw、pitch）、`torso`（ankle_pitch、knee_pitch、waist_pitch、waist_yaw）、`left_arm` / `right_arm`（各 J1～J7）。使用选中姿态已保存的关节值，弧度自动换算成角度；缺少有效关节值时提示失败。复制内容可另存为 JSON 后导入预设姿态。
- **复制停车点**暂采用 `format: "atlas-route-studio-parking-point"`、`version: 1` 的 JSON：包含任务身份、机器人与地图身份、坐标系和米 / 角度单位，以及 `parkingPoint` 的名称、顺序、底盘位姿和全部下属姿态（含关节值及光学目标）。不复制图片或点云；原生记录缺少定位时带 `located: false`。此格式独立于机器人导出 ZIP，后续可按机器人端约定调整。

点击“另存为工程”后先打开系统保存对话框，可选择目标文件夹并修改 ZIP 文件名；确认后才开始打包，文件写入完成后提示保存成功，并启用“保存工程”。再次另存为成功后，“保存工程”改为覆盖新文件；取消或失败时仍保留原来的保存目标。示教数据页的“导出工程”也使用这一另存为流程。重命名针对工程文件，不更改地图、机器人或示教任务名称。

无论在哪一侧点击“另存为工程”“保存工程”或示教数据页的“导出工程”，都会收集两侧当前工作区（包括尚未绑定的一侧）和完整独立示教缓存列表。每组保留完整的模型、机器人、预设姿态、路径、示教任务和视觉资源引用；内容相同的二进制资源在包内只保存一份。同名、同点云的不同示教组保持独立身份，当前及历史转换矩阵、矩阵导入记录和提取回写基线一并保留，加载后仍可独立编辑。缺失任何历史组的必要资源时保存失败，不会生成漏项的“完整工程”。使用系统保存对话框成功保存后，包内两侧工作区共用该保存位置；刷新或切换模式后可继续保存，浏览器可能再次要求文件写入授权。新建或加载另一工程后须重新另存为，避免覆盖原工程。每次“保存工程”都会重新打包当前数据，写入成功后才提交替换。

完整集合及双边工程 ZIP 可以从地图示教或独立示教的加载入口打开：系统先校验全部资源，再一次性恢复工作区和独立示教列表，并进入包内与当前入口对应的模式（若不存在则进入保存时的模式）。加载后切换工作区或历史组无需再导入模型；之前已同步到独立示教中的地图路径会按绑定关系重新计算显示，地图绝对坐标及各组原坐标不变。目标设备上无关的独立示教缓存会保留。缺少资源、校验失败或缓存写入失败时不会提交部分恢复结果。旧版单边 ZIP / JSON 和双边 ZIP 继续兼容，但旧包中原本未保存的历史组无法凭空恢复。

双边工程的逻辑清单仍为 `atlas-route-studio-linked-project` v1，`workspaces/map/`、`workspaces/independent/` 分别描述两侧完整的 v2 工程资源。解压后也可选择根目录一次性导入双边快照；这种根目录不启用增量写入，后续使用 ZIP 保存。原有单边工程目录的增量写入方式保持不变。

含历史列表或未绑定双工作区的完整集合，其逻辑清单为 `atlas-route-studio-workspace-project` v1，`workspaces/` 描述当前工作区，`independent-history/<序号>/` 描述每个历史组的完整 v2 工程资源。清单记录历史顺序、保存时间及各文件 SHA-256；机器人实际资源随包携带，换设备无需预先复制机器人目录。集合解压后也应选择根目录加载，后续用 ZIP 手动保存。

存在重复资源或可复用的地图放置时，ZIP 使用 `atlas-route-studio-resource-project` v1 存储清单：`projectManifest` 保留上述逻辑清单，`files` 校验实际文件，`references` 描述共享资源及几何重建步骤。配置 JSON 保持原目录路径；模型几何、原始 PLY、机器人网格和视觉资源按内容共享。两个模型建立三十个独立示教组时，每种模型资源只保存一份，三十组的配置与转换关系分别保留。地图中已放置的模型在原始资源可用且变换结果逐位一致时，保存为源几何与变换；无法确认的旧数据或编辑后的几何保留原字节。加载时先恢复并校验原文件，再交给现有解析、渲染及碰撞逻辑，因此不会改变坐标、精度或组间编辑隔离。浏览器运行时的几何及缓存结构不变。

新版本可直接读取旧 ZIP，无需迁移；无可共享资源时仍生成原有格式。共享资源包需使用支持该存储格式的版本打开。解压后仍选择整个根目录，不能单独复制某个组。单工作区目录继续支持增量保存；修改共享照片时会保留其他姿态仍在引用的旧内容。回归检查：`npm run test:project-storage`。

浏览器未提供原生保存对话框（例如部分浏览器或普通 HTTP 局域网访问）时，显示工程命名弹窗，补全 `.zip` 后按浏览器下载设置保存。网页无法覆盖这种下载文件，因此下载后“保存工程”不可用，需要继续使用“另存为工程”。如需选择位置，可在浏览器中开启“下载前询问保存位置”。另存为位置不会绑定为工程目录自动保存位置。

新建 PLY 工程默认受浏览器自动保存保护。需要持续写入本地文件夹时，先“另存为工程”，解压 ZIP，再通过对应模式的“加载工程 → 选择其他工程目录”打开并授权；后续修改会增量保存到该目录。也可以在其他设备通过“加载工程引导文件”直接打开 ZIP。工程 ZIP 仅在手动另存为或保存时更新。

独立示教保留的轻量示教数据采用 `format: "atlas-route-studio-teaching-data"`、`version: 1`，与完整工程格式独立。主要字段：

- `source`：来源示教模式及地图名称 / 哈希；`coordinateSystem`：坐标系、米 / 角度单位、ZYX 欧拉角顺序和列主序矩阵约定。
- `robot`：机器人身份、当前基座 `mapPose` 和按关节名称保存的 `fullBodyJoints`；关节记录分别标明旋转与平移单位。
- `tasks[].parkingPoints[].poses[]`：保留 ID、名称、顺序、停车位姿、逐 Pose 基座位姿、全身关节值和光学目标位姿。
- `navigation` 与 `jointPoses`：导航点 / 路径引用、速度约束和关节姿态库。
- 已接收的 iPad / Vision Pro 任务保留设备 Pose、校准矩阵及 `mobileTransform`；不包含模型、RGB、点云、预览资源、界面状态或求解报告。

当前实现通用示教数据导出，跨工程合并导入尚未接入。后续导入需匹配机器人与关节名称、对齐源 / 目标坐标系，并处理任务和点位 ID 冲突。工程加载入口会明确拒绝轻量示教 JSON，避免将它当成工程配置替换当前现场；旧版工程 JSON 和完整 ZIP 仍可加载。

验证：`npm run test:teaching-data`、`npm run test:project-save`；节点操作切换与剪贴板测试：`uv run --with playwright python tests/teaching_copy_ui_smoke.py`；浏览器入口与跨设备恢复测试：`uv run --with playwright python tests/export_separation_ui_smoke.py`；保存对话框、取消与重命名测试：`uv run --with playwright python tests/project_export_save_ui_smoke.py`；覆盖保存、目标切换、权限失败与刷新恢复测试：`uv run --with playwright python tests/project_save_target_ui_smoke.py`（先启动服务）。

## 完整工程目录

```text
工程目录/
├── atlas.project.json        # 工程入口
├── manifest.json             # 完整性与资源身份，最后写入的提交标记
├── config/project.json       # 实时配置
├── environment/              # 地图 Float32 坐标、RGB8 颜色与原始面索引
├── robot/files/              # 模型、网格、纹理与包清单
└── teaching-data/<任务>/<停车点>/<姿态>/
    ├── pose.json
    ├── rgb/                  # 左右 Zivid RGB
    └── pointcloud/            # left / right 量化点云
```

跨设备迁移时，压缩整个工程目录，并在目标设备解压后打开，保持目录层级完整。

<details>
<summary>目录增量写入与工程迁移</summary>

- 工程的日常形态是一个可直接打开的普通文件夹，根入口为 `atlas.project.json`，完整性与资源身份记录在 `manifest.json`，实时配置位于 `config/project.json`。
- `environment/` 无损保存地图 Float32 坐标、RGB8 颜色和原始三角面索引；
- `robot/files/` 保存 URDF/GLB/GLTF/STL 及其网格、纹理和包清单；
- 视觉数据按 `teaching-data/<任务>/<停车点>/<姿态>/` 分层，每个姿态有独立 `pose.json`，左右 Zivid RGB 位于 `rgb/`，量化点云位于 `pointcloud/<left|right>/`。
- 从顶栏“加载工程”进入恢复窗口并选择这个解压后的目录后，导航图、机器人状态、2D/3D 视角与示教配置会直接从目录恢复；之后可直接从置顶的默认保存路径再次加载。
- 后续修改只会增量改写 `config/project.json`、对应的姿态元数据和首次出现的 RGB/点云，再以 `manifest.json` 作为最后提交标记；固定地图和机器人资源不会随每次操作重复写入，也不会在后台反复生成 ZIP。
- 底栏 `PROJECT SAVING / PROJECT SYNCED` 显示目录写入状态。
- 跨设备迁移时由使用者人工压缩整个工程目录，并在目标设备人工解压后继续打开；必须保持目录层级完整。
- 原有 ZIP/JSON 读取仍作为兼容入口保留在恢复窗口的“加载工程引导文件”按钮中。

</details>

### 两套工作区

- 地图示教与独立示教使用两套相互隔离的工作缓存。
- 主页面的两个模式卡会分别显示“已缓存”状态；选择模式后点击“继续工作”，系统会先完整保存当前模式，再激活所选模式的地图、机器人、导航图、示教任务、工程目录关联以及 2D/3D 视角。
- 两种模式可以反复切换而不会互相覆盖，刷新后仍会恢复最后激活的模式；新建工程只替换对应模式的缓存，并明确保留另一种模式。
- 底层 IndexedDB 通过活动槽索引直接读取目标缓存，不会为了切换而复制大型点云缓冲。

### 缓存内容

| 分类 | 自动保存内容 |
| --- | --- |
| 场景 | 已解析的点云坐标 / 颜色、原始三角面、Z 截面范围与跨度 |
| 机器人 | 模型选择、基座位姿、当前关节值、逐关节 IK 锁定、命名姿态库 |
| 示教与导航 | 虚拟示教任务与点位、导航点、有向路径、运动约束、行驶策略、连通性状态 |
| 视角与显示 | 2D 中心 / 缩放，3D 位置 / 旋转 / 缩放 / 精密平移，配色与网格质量 |

### 刷新与恢复

- 视角另有一份轻量同步快照，用于覆盖“刚结束拖拽就立即刷新”时异步保存尚未完成的时间窗口。

- PLY 只在首次载入时解析，同一次服务运行期间刷新或稍后重新打开页面会直接恢复几何缓存、机器人模型、机器人基座、当前关节值、逐关节 IK 锁定、关节姿态库、示教记录和两个窗口的上次视角。碰撞保护在刷新后默认开启，并等待地图与机器人就绪后自动检测；机器人键盘控制开关、机械臂末端控制模式及临时的末端锁定状态在刷新后恢复为关闭，已求解并锁住过的最终关节姿态仍会保留。

- 带 mesh 的 PLY 会额外缓存原始三角面索引；首次以新版本重新选择一次文件后，后续刷新可直接恢复混合渲染，不会再次解析数百万个 face。

- 大型点云与便携机器人资源合计超过 64 MiB 时，二进制数据以 Blob 存入缓存，避免超过浏览器单条记录的序列化上限而中断工程导入；刷新、服务重启恢复和空间转换均还原原始字节，不降低地图精度。

- 导出的导航点同时包含通用的 `pose` 对象，以及兼容字段 `xzy`（`[x, z, y]`）和 `rpy`（`[roll, pitch, yaw]`）。

</details>

<details>
<summary>工程加载、浏览器权限与服务重启恢复</summary>

- 主页面的“加载工程”会先打开恢复窗口。
- 窗口仅在所选示教类型内，按“已记住的默认工程目录 → 本地自动保存工作区 → 服务重启保护副本”的顺序提供主加载动作，并保留“选择其他工程目录”和“加载工程引导文件”两个明确入口。
- 选择工程引导文件时默认仅显示 JSON 配置与 ZIP 工程包；支持原生文件选择器的浏览器会隐藏“所有文件”选项，其他浏览器使用相同扩展名过滤，并在导入前检查扩展名。
- ZIP 在单个后台任务中逐项解压，显示解压与完整性校验进度，避免同时解压大量机器人资源时反复复制整个压缩包、耗尽内存。
- 解压、全部工作区与历史缓存校验、结果恢复共用一条总进度条；进度只向前推进，恢复后的页面沿用原进度，完成时显示 100%。加载期间固定显示工程文件名，仅更新阶段说明。
- 加载失败时，弹窗会持续显示所选文件名和具体原因，直到手动关闭或点击“重新选择工程”；完整工程校验失败时不会替换已有工作区或历史缓存。
- 选择包含 `atlas.project.json`（新工程）或 `manifest.json`（兼容既有 v2 工程）的文件夹时无需先压缩。
- Chrome/Edge 在 `localhost` 或 HTTPS 安全上下文中可授予目录读写权限，权限句柄按地图示教/独立示教分别保存在 IndexedDB；浏览器刷新后会继续增量保存，服务更新后仍随本设备工作区恢复，不因服务进程变化创建空白工作区。
- 若浏览器或普通局域网 HTTP 页面不提供目录写入 API，则自动回退为完整目录读取，并明确显示 `PROJECT READ ONLY`，当前工作仍由浏览器会话自动保护。
- 服务更新或重启不会主动刷新页面或清空工作区；浏览器重新打开后直接恢复本设备的地图解析缓存、导航图、机器人与关节值、示教任务、当前选择及 2D/3D 视角。历史版本留下的保护副本仍可从恢复窗口或“示教数据”页加载。
- 恢复只替换副本所属示教类型的工作缓存，保留另一种类型的缓存和视角；恢复成功后临时副本会自动清理，避免长期保留同一份大点云两次。
- 底部状态栏的 `SESSION AUTO-SAVE` 表示浏览器自动保护正常，`PROJECT SYNCED` 表示工程目录增量写入正常，`RECOVERY READY` 表示存在可恢复的未完成工程。
