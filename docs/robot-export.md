<a id="机器人示教数据导出"></a>

入口：**地图示教 → 示教数据中心 → 导出示教数据 → 下载机器人导入包**。已绑定地图并开启路网同步的独立示教，也可在“导出示教数据”中选择“地图示教任务 ZIP”进入同一校验窗口；“独立示教任务 JSON”保留原轻量导出。

| 文件 | 用途 | 机器人侧使用方式 |
| --- | --- | --- |
| `robot-teaching-*.zip` | 兼容机器人 / 实例的大脑示教任务包 | 在大脑 Web“示教任务 → 导入”中直接选择，无需解压 |
| 完整工程 ZIP | 虚拟工程备份，由“导出工程”生成 | 在虚拟示教平台打开 |
| `robot-navigation-*.json` | 路网、坐标与导航 / Pose 对应清单 | 在导出窗口单独下载，用于核对；同样保存在任务 ZIP 的 `navigation.json` 中 |

机器人导出按提供的 `ABXBrainSystem.zip` 中现有 **v23** 导入器生成任务，ZIP 清单为 **v1**。每个非空停车点的首个 Pose 前，以及停车点内底盘目标变化处，导出 `route_navigation` 步骤，随后执行对应 Pose。完整路网内嵌在任务的 `navigation_chunk` 中，并附带 `routes/` 副本；在大脑“示教任务 → 导入”选择 ZIP 后，现有导入器自动恢复路网并将任务绑定到导入的路网，无需修改机器人工程。保留原始节点编号（包括 `N0` 和不连续编号）、全部连线、坐标、朝向及 `scene_name`，不只导出示教使用的站点。

**预设姿态随任务同步导出**：在“机器人 → 新建预设姿态”中保存的预设，会按任务对应的机器人写入每个任务的基础姿态库，未插入任务的预设也会携带。导出窗口显示随包预设 / 基础姿态数量；导入后可在机器人的基础动作库中使用，不增加任务执行步骤。记录采用 `teaching-tasks.zip` 示例的 `basic_pose` 字段、20 关节弧度数组和计数 / SHA-256 规则，与现有 v23 格式兼容。原生任务已有的基础姿态继续保留；其他机器人的预设不混入当前任务。已绑定地图的独立示教导出 ZIP 时携带当前独立工程的预设。预设缺少关节、单位非法或包含无法表达的关节时，阻止整包下载并显示对应预设名称。

导入路网后，导航点按 **`N<原始 id> · <label>`** 命名，列表排序和重复名称不会改变站点身份。以 `1019平地路网终版测试.json` 为例，四组“停车点1”分别显示为 **N1、N31、N62、N98 · 停车点1**。旧缓存中的机器人节点加载时也会补充编号；独立示教同步保留这些名称。在导航点上新建任务并记录当前位置、添加停车点时，会沿用该路网站点名称。

导出时，已加载路网的任务按地图 XY 位置匹配原生站点（容差 0.1 mm），Z 高度和微小朝向差异不会触发重新编号，导航使用路网定义的坐标与朝向。对于指定了朝向的路网站点，底盘朝向差超过 0.1° 时提示对齐，避免改变原示教意图。同位置的示教标记复用路网节点；停车点或 Pose 无对应站点、原路网结构缺失时阻止导出，不自动生成新的 `N` 编号。同坐标有多个站点时，用停车点名称中的明确 N 编号或唯一匹配的朝向区分；仍有歧义时提示修正。任务包中的停车点名称同步使用对应路网编号和名称，原始记录的地图坐标不被修改。

独立示教同步路网后，“运动到该点”会在保留机器人当前 Z 高度的同时，按转换矩阵对齐地图中的站点 XY；矩阵含 roll/pitch 倾斜时也不会因保留高度而偏离站点。旧版本按局部 XY 定位、保留高度后产生的偏移，导出时可根据工程保存的放置矩阵和停车点名称中的明确 N 编号识别，窗口会显示兼容提示；核对高度投影后仍须满足 0.1 mm 的位置容差和原朝向要求。原记录与关节值保持不变，随包路网复用已有站点，不增加重复节点。

地图和独立示教的 3D 名称标签会将同一路网站点与对应示教停车点合并显示，选中任一对应点时共用标签保持高亮。按 N 编号（兼容旧名称）和位置唯一关联，显示层允许 5 cm 内的小幅偏移，并考虑独立坐标系的高度投影；不同编号、明显移开的点或有歧义的站点仍分别显示。独立模式同步带入的地图停车标记也参与去重。此处理只影响名称标签，原始点、选择目标、路径、示教记录和机器人导出校验保持原状。验证：`npm run test:waypoint-labels`、`tests/waypoint_label_groups_ui_smoke.py`。

新增或修改路网后，直接重新导出示教 ZIP 即可携带当前路网；右侧 **图谱控制台 → 路径 / 导航 → 导出路径** 仍支持单独导出 `.route.json`。导出窗口显示随包路网、节点与有向边数量，并预览导航编号及坐标。旧版原生任务只含站点编号时，使用工程中唯一的已导入路网补齐关联；缺少目标节点或存在多个候选路网时提示修正。没有导入任何路网时，保留旧任务原始格式、显示“—”及未携带路网提示，不编造定位。

`380B平地巡检.zip` 用于旧格式兼容验证，其 N10、N11 不在 `1019平地路网终版测试.json` 中，不能直接将这两个参考文件配对运行。1019 示例保留 40 个节点、92 条有向边和 `big_map_1` 场景名称；测试以实际存在的节点验证导出与机器人端导入。

## 机器人文件双向交换

打开地图示教工程后，在 **示教数据中心 → 示教数据树** 中选中任务，即可显示机器人示教导入、导出入口；选中停车点、姿态或没有任务时不显示导入按钮。顶部 **示教菜单** 保留示教数据页面与示教转换入口，路径导入导出位于右侧 **图谱控制台 → 路径 / 导航**：

| 操作 | 文件与行为 |
| --- | --- |
| 示教数据树 → 导入机器人示教 | 选择机器人导出的 `abx-teaching-export` ZIP 或单个 `.abxteach.ndjson`；每次以新任务追加到当前工程，保留选中任务及其停车点、姿态，同名或重复导入也不覆盖已有任务。同时导入随任务携带的路网和基础姿态。 |
| 示教数据树 → 导出示教数据 | 下载机器人可直接导入的任务 ZIP；支持新建的虚拟任务及从机器人导入的原生任务一起导出。 |
| 路径 / 导航 → 导入路径 | 选择机器人“路网管理 → 导出路网”得到的 `.route.json`，追加节点与有向连线。 |
| 路径 / 导航 → 导出路径 | 下载 `schema_version: 1` 的 `.route.json`，在机器人“路网管理 → 导入路网”使用；多个路网可分别选择下载。 |

- 提供的 `ABXBrainSystem.zip` 已支持任务内嵌路网，本次适配只修改虚拟示教工程，不需要修改机器人程序。原始源码 ZIP 保持不变；契约测试在临时数据库中运行，不连接机器人。
- 原生任务和完整工程保留导入的完整记录，可读取至 v23；默认机器人 ZIP 不再降级为 v11。指定执行部位、基础姿态库、等待、并行、Cartesian、通知、录制轨迹和拍照配置按原生记录保留，保留动作 ID、纳秒时间戳和步骤顺序。没有附加路网的旧任务保持原版本；为旧任务补齐路网时仅升级必要的文件头和计数、追加导航分块，不重写已有停车点和动作。
- 可修改任务 / 停车点 / Pose 名称和独立 Pose 的关节值，也可通过“插入动作”在独立 Pose 前后插入已保存的机器人预设姿态，通过“上移 / 下移”调整同一停车点内、不跨导航步骤的姿态顺序；虚拟回放只展示独立关节 Pose，不执行机器人动作。其他原生步骤结构调整仍需在机器人端完成后重新导入；结构对应关系不完整时阻止导出。
- 路网节点 ID、边 ID、方向、定位场景绑定与中间节点的 `yaw_rad: null` 通过独立 `.route.json` 往返保留。坐标为米，工作台角度为度，机器人文件角度为弧度。机器人路网格式没有逐边速度、加速度、倒车和避障字段，这些设置仅保存在完整虚拟工程。
- 无 map 定位的原生停车点不会生成虚假的原点导航点，也不能用于底盘恢复或地图回放。原生定位记录作为历史测量保留；更改导航目标应编辑对应路网节点。
- 导入验证版本、UTF-8、记录数量 / 顺序、路网引用、关节单位和正文 SHA-256。文件缺失、损坏、同 ID 路网冲突时整批拒绝，当前工程不受影响。ZIP 内的历史图像不转换成虚拟相机快照，仍保留在来源 ZIP 中。
- 原生数据及路网身份会随会话保存和完整工程备份保存。`robot-navigation-*.json` 仍是核对清单；机器人路网管理应使用 `.route.json`。

运行 `npm run test:abx` 验证完整路网打包、旧任务补齐路网、站点身份、关节单位和正文 SHA-256。存在 `ABXBrainSystem.zip` 时自动使用其原始浏览器 ZIP 读取器及 Python 导入器验证任务关联、执行计划和既有路网不被覆盖；存在 1019 路网时额外验证 40 节点、92 边及定位场景。`npm run test:abx-v11` 保留显式旧版导出兼容验证，380B 示例任务在无修改往返后逐字节一致。完整工程扩展契约可运行 `ABX_WORKSPACE_ZIP=ABXBrainSystem.zip npm run test:abx-extended`。

执行前，在机器人路网管理中核对地图坐标、站点编号和连线，并**切换使用对应路网**。导入任务本身不会激活路网或切换定位地图。RGB / XYZ 快照仍是虚拟工程参考数据，不会新增真机拍照动作。

## 导出前检查

- 机器人型号匹配实际 URDF，**20 个全身关节**按名称映射并转换为弧度。
- 地图与机器人一致，姿态已处于地图坐标，坐标与现场地图对齐。
- 关节没有缺失或超出格式范围；未求解为关节值的 iPad 相机 Pose 会阻止整批机器人数据生成。
- 单独机器人导入包包含 **1–100 个任务**；下载的是当前快照，目录自动保存不会更新已下载文件。

机器人导出失败时，仍可保存完整虚拟工程备份。

<summary>归档协议、路网导航与执行边界</summary>

### 机器人 ZIP 格式

- 地图示教的“示教数据中心 → 导出示教数据”提供 `robot-teaching-*.zip`，可在大脑 Web“示教任务 → 导入”中直接选择，无需解压。
- ZIP 包含根目录 `manifest.json`、`README.txt`、`tasks/<32 位十六进制 ID>.abxteach.ndjson`、关联路网的 `routes/` 副本及导航与源数据清单。清单为 `abx-teaching-export` v1；新任务及补齐路网或预设的旧任务为 `abx-teaching-task` v23，未附加路网或预设的原生旧任务保留原版本。
- 新建虚拟任务的记录依次为文件头、全部停车点、全部步骤、预设姿态（`basic_pose`）、导航分块和结束记录；`basic_pose_count` 与实际预设数量一致，同一预设在不同任务中使用稳定 ID。计数、序号和纳秒时间戳使用字符串。结束记录的 SHA-256 对正文各行及其 LF 换行计算，不包含文件头和结束行。原生任务的记录顺序保持不变。
- 原生步骤的 `action: {id, name}` 保留；全身关节按头部 2、躯干 4、左臂 7、右臂 7 的固定顺序转为弧度。虚拟 Pose 使用 `component=auto`，由大脑根据实况判断执行部位。
- 虚拟姿态的 `parking.location=null`，不伪造测量定位；`robot_received_ns="1"` 为格式占位，`robot_sequence` 为导出步骤序号。原生任务保留原值。
- 清单使用 `include_images=false`、`images=[]`、`pending_captures=0`、`image_count=0`；保留原任务中的拍照配置，不打包虚拟图像、不执行拍照。
- ZIP 使用存储模式，兼容不提供 Deflate 解压的 WebView。
- 导出只需读取主 URDF，不重新打包地图、mesh 或视觉资源。
- “导出工程”生成完整虚拟工程备份；机器人适配包由“导出示教数据”单独生成。兼容读取既有附带 `abx/` 目录的完整工程 ZIP。

### 大脑接口边界

- 新任务使用 `{type: "route_navigation", route_id: "…", node_id: "N…"}` 动作。旧任务的节点引用保持原始记录，通过内嵌导航上下文的 `default_route_id` 关联唯一的工程路网。机器人现有导入器恢复路网并重映射任务引用，不覆盖既有业务路网、不切换当前激活路网。
- 已导入机器人路网时，仅引用原生节点 ID，不以停车点名称、数组下标或示教记录顺序生成编号；同坐标站点的 yaw 使用周期角比较。没有导入机器人路网的手绘工程仍可生成新路网，需先在机器人上导入并启用该路网后再执行任务。
- 连线只取工程内已有路径，保持方向；无向路径转为两条有向边。同一连接去重，不按 Pose 顺序或距离自动生成可通行连线。
- 没有入向连线、相邻导航步骤无有向通路时，导出窗口和清单提示需补齐路径，仍保留数据供机器人侧核对。
- 已导入路网保留原 `scene_name`；新建虚拟路网的该字段留空，点云文件名 / 摘要不是机器人 SLAM 场景名称。导入包不包含 SLAM 地图文件，机器人需具备并定位到相应场景。
- 仅在虚拟示教工程中生成文件，不连接机器人、不写入 `workspace` 或运行中的大脑数据库。

### 导航数据字段

- 单独下载的 `robot-navigation-*.json` 使用 `atlas-abx-route-navigation` v1，标注 `nativeTaskNavigationSupported=true`、实际 `taskVersion` / `taskVersions` 和 `routeImportIncluded`，包含参考路网、原导航点、提示和每个任务的步骤映射。混合版本时 `taskVersion=null`，以 `taskVersions` 为准。
- `tasks[].sequence` 记录 `route_navigation` 与 Pose 顺序、原生步骤序号、节点和目标坐标；`tasks[].parkings` 保留停车点、Pose 与节点对应关系。
- 目标使用 `map` 坐标系的 `x_m`、`y_m`、`yaw_rad`，yaw 归一到 `[-π, π]`；可在窗口预览或单独下载 `robot-navigation-*.json`。
- `navigation.json`、`source-mapping.json`、`free-navigation.json` 和关联的 `routes/` 副本随默认机器人 ZIP 导出；机器人实际从任务内嵌分块恢复路网。完整工程继续保留原地图、路径和配置，不受机器人导出影响。

### 关节映射与导出校验

- 机器人型号由实际 URDF 名称确定；20 个全身关节按名称映射并转为弧度，不补零。
- 缺失关节、超出格式的额外关节、地图或机器人不一致、非地图坐标，以及尚未求解为机器人关节的 iPad 相机 Pose 会阻止整批机器人数据生成；完整虚拟工程备份仍可正常保存。
- 轮组不作为上身关节执行，`parking.location=null`，不伪造实测定位；RGB/XYZ 仍为虚拟工程中的参考快照，不新增真机拍照动作。
- 单独的机器人导入包支持 1–100 个任务；导出为当前快照，目录自动保存不会更新已经下载的文件。
- 每个任务最多 2000 个步骤（包含新增导航步骤）、128 个非空停车点；共享路网最多 256 个节点、512 条有向边和 48 KiB。超限或路径引用错误会阻止整包生成，不产生部分导入包。
