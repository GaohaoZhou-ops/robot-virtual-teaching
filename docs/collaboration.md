## 两台浏览器同步作业

默认各设备独立作业：未点击同步按钮的远端不注册同步会话、不进行 3 秒轮询，也不上传示教数据。ZIP 解压、场景渲染、姿态调整和默认碰撞计算在访问设备本地完成。Mac 页面通过被动通知接收授权申请；只有申请获批后才启动双方每 3 秒的数据交换。断开或到期后立即停止该定时通讯。

1. 在运行服务的 Mac 浏览器中打开要协作的地图示教或独立示教工程，并保持页面打开。
2. 另一台设备访问该 Mac 的局域网地址，在欢迎页 `LAN :21990` 右侧点击 **同步作业**。
3. Mac 弹出授权窗口；点击 **允许同步（5 分钟）** 后，另一端自动拉取当前工程的模型、机器人、导航路径、预设和示教结果。
4. 双方每 **3 秒**交换改动，按任务、停车点和 Pose 标识合并；当前选择、机器人实时操控和视角留在各自设备。请按 SOP 分别示教不同停车点。
5. 连接后双方按钮显示 **断开链接**，欢迎页和工作台均可操作。任意一方断开、授权到期或切换工程都会停止同步，已经同步和本地示教的结果继续保存在各自浏览器中。

另一端可随时点击 **重新申请授权**；待审批时也可再次点击 **同步作业**提交最新申请。每次批准从当时起重新计时 5 分钟。对同一工程重新授权，会合并断开期间的本地改动。同步范围是当前打开的工作区，切换模型、机器人或示教模式后需要重新授权；服务重启或页面重新打开后也需重新申请。

欢迎页 **同步作业** 旁提供 **全局重置**。警告弹窗确认后，先断开本设备的同步，再清空本设备的地图示教、独立示教及全部历史缓存、恢复副本、同步检查点、模型编辑现场与撤销记录、记住的工程保存位置，然后返回欢迎页。已导出的 ZIP / 工程目录文件、原始模型以及其他设备的结果保留；取消不会清理任何数据。

## iPad 画面协作：扫码、Wi-Fi 与数据线

在电脑上操作虚拟机器人时，可在 iPad 上查看左右臂 Zivid 2 M70 仿真画面，或拖动关节并查看与电脑同步的 3D 姿态。无需先把模型传到 iPad。

iPad 的产品定位：**配备 LiDAR 的 iPad Pro 支持本机虚拟示教与画面协作；iPad mini、iPad Air 和普通 iPad 仅支持画面协作**。画面协作不需要 LiDAR，非 LiDAR 真机默认进入“画面协作”等待页；“接收物体”和本机虚拟示教区域保留并置灰，不能打开。协作中的相机画面、关节调整、3D 视角手势和记录姿态均可使用，记录结果写入电脑工程。iPhone Pro 的 LiDAR 示教保持支持；模拟器仍保留模型预览以便开发验证。

| 电脑 | 支持的协作连接方式 |
| --- | --- |
| Windows | 扫码、Wi-Fi 配对码、数据线（本机连接助手） |
| Mac | 扫码、Wi-Fi 配对码、数据线 |

1. 更新并启动电脑服务。本机可通过 `http://127.0.0.1:21990` 打开，其他电脑通过服务器的局域网地址打开地图示教或独立示教工程，加载带左右臂末端相机的机器人。进入 **设备 → iPad / iPhone → 画面协作**。
2. iPad 打开新版 Atlas App，选择下列一种方式连接：
   - **扫码**：电脑选择 **扫码** 后自动展示二维码，可点击 **重新生成二维码** 刷新。iPad 在首页点击 **扫码配对**，App 自动识别协作用途并进入协作页面，无需先选择“画面协作”。
   - **Wi-Fi**：电脑选择 **Wi-Fi → 生成配对码**；iPad 首页选择 **画面协作**，填写电脑窗口显示的局域网地址与端口，搜索并选择服务器，输入 4 位配对码。
   - **数据线**：连接、解锁并信任电脑，保持 Atlas App 在前台。在服务器本机 Mac 使用 `localhost` 或 `127.0.0.1` 打开工作台；Windows 或通过局域网地址打开工作台的其他电脑，先按下方说明连接本机助手。**电脑发起**：选择设备后点击 **发起邀请**，在 iPad 的确认弹窗点击 **接受邀请**。**iPad 发起**：在首页“数据线连接（USB）”提示卡点击 **邀请电脑协作**，电脑当前工作台会弹出确认窗口，点击 **接受邀请** 后开始；无需先打开电脑的“画面协作”窗口。打开窗口或检测到设备不会自动发起邀请。电脑到 iPad 的有线协作不依赖 Wi-Fi，仍兼容 iPhone。
3. iPad 顶部切换 **相机画面 / 关节控制**。相机页横屏并排、竖屏上下排列；轻点画面或使用切换按钮可放大单臂，再次轻点返回双臂。
4. 关节页横屏并排显示 3D 视图与滑块，竖屏上下排列。在 **3D 姿态** 画面内，**单指拖动旋转、双指开合缩放、双指拖动平移**；双指缩放和平移可以同时进行。iPad 和电脑同步共享视角，手势不改变机器人位姿或关节值。关节面板可选择左臂、右臂、躯干等分组；角度或米数与限位来自当前机器人。拖动关节同步修改电脑的虚拟机器人，电脑调整也会回传数值与画面。轨迹播放或 Pose 记录期间暂停关节操作，仍可调整观察视角。
5. 相机页与关节页右上角均可点击 **记录姿态**，复用网页端记录流程，把当前全身关节、机器人位姿及双目 RGB/XYZ 快照保存到当前任务的停车点。关节页的记录结果显示在 **3D 姿态** 标题旁；相机页显示在画面切换控件旁。**结束协作** 位于左上角标题右侧，底部空间留给画面与关节。任务与停车点需要先在网页端新建或选择；缺少任一项时，iPad 弹窗提示对应操作。底盘偏离停车点、正在编辑姿态或播放轨迹时，也需先在网页端处理。iPad 不提供任务与停车点管理。
6. 关闭电脑协作弹窗、切换电脑窗口、桌面或浏览器标签页后仍保持连接，无需重复开始协作。浏览器暂停渲染时，iPad 保留最近画面并提示等待更新，返回工作台后自动继续。任一端结束协作、切换工程、关闭工作台或 iPad App 退出前台会停止协作。

扫码与 Wi-Fi 使用同一局域网通道，两种入口可切换并保留当前配对码。电脑可以通过网线接入路由器，iPad 使用同一网络的 Wi-Fi；多个网卡时选择 iPad 能访问的地址。Windows 启动服务时允许 Node.js 通过专用网络防火墙，并确保服务端口（默认 21990）可从局域网访问。访客 Wi-Fi、设备隔离或 VPN 可能阻止互通。配对码有效 15 分钟、仅允许一台 iPad；可点击 **更新配对码**，旧码随即失效。服务重启或协作结束后需重新配对。

其他电脑只需在浏览器打开本服务，就能为自己的当前工程生成协作二维码，**无需先同步工程或安装另一套服务**。二维码中的地址是协作连接地址，画面和关节来自发起邀请的浏览器，记录姿态也只写入该浏览器当前工程。每个协作会话使用独立配对码与凭据，多台电脑的协作互不覆盖；关闭其中一个不会中断其他会话。iPad 如需切换电脑，先结束当前协作，再扫描另一台电脑的二维码。

## Windows 数据线连接助手

**Windows 数据线协作（浏览器仍访问 Mac 服务器）**：

1. 首次使用，安装 [Python 3.9 或以上](https://www.python.org/downloads/windows/)，以及 Apple 的 **Apple 设备** App（或包含 Apple Mobile Device Support 的 iTunes）。连接 iPad、解锁并信任电脑，确认 Apple 设备 App 能识别它；参见 [Apple 官方连接说明](https://support.apple.com/zh-cn/108643)。随后在 iPad 前台打开 Atlas。
2. 工作台进入 **画面协作 → 数据线 → 下载数据线连接助手**，完整解压，在 Windows 双击 **start-windows.cmd**，保持控制台运行。无需安装整个工程，也无需安装额外 Python 包。
3. 点击 **连接本机助手**，在新窗口核对工作台地址并点击 **允许连接此工作台**。随后可从电脑点击 **发起邀请**，或从 iPad 点击 **邀请电脑协作**，由接收方在弹窗确认。浏览器拦截助手窗口时，请允许当前工作台打开弹窗后重试。
4. 返回原工作台继续使用，助手窗口可最小化，但需保持打开。关闭助手程序、助手窗口、工作台或结束协作会断开；重新打开助手后可以再次连接。Mac 远端工作台也可通过 `python3 ipadUSBBridge.py` 使用同一助手。

助手仅监听 `127.0.0.1:21994`，通过本机窗口间消息传递画面与指令，**不经 Mac 服务器中转协作画面**。工程仍留在原浏览器地址，未同步的本地工程、任务和停车点保持原位；记录 Pose 也写入原工程。访问页面、初次加载模型等仍需要能访问服务器。使用双向邀请需同时更新 iPad App、电脑服务并重新下载助手；不支持邀请确认的旧版 App 会提示更新。助手只提供协作，不提供设备文件访问、App 安装或模型传输。

## 连接状态与传输行为

有线邀请有效期为 **60 秒**。接收方可拒绝，发起方可取消；取消后对端会撤下邀请窗口，未响应或失去连接的邀请不会自动建立协作。确认前不发送画面、关节状态或控制指令。iPad 邀请由前台工作台接收，多个工作台同时接受时只允许一方建立连接；取消、拒绝和过期的邀请不能重用。扫码和 Wi-Fi 入口在欢迎页保持展开，扫描或输入配对码仍是明确的加入动作。

协作复用原有扫码器、地址输入、服务器检测和配对码控件；**接收物体** 与 **画面协作** 在首页区分，二维码自带用途，避免误触发模型接收或结果上传。App 更新可运行 `./scripts/deploy_ipad.sh`，覆盖安装保留已有项目。

画面来自当前虚拟工程，保留完整相机视野，电脑相机面板的数字缩放不改变共享画面。超过 2.5 秒未收到新画面或关节状态时提示等待更新、暂停滑块；连接保活与画面刷新独立。滑块只调整虚拟姿态，点击 **记录姿态** 才会保存 Pose。记录期间暂停关节操作和重复点击；请求重发不会重复保存，任务或停车点在记录期间切换会取消本次记录。每个关节仅保留最新指令，超过 3 秒未送达的操作会丢弃。

无线方式由 iPad 主动连接服务端 WebSocket，配对后共用有线协作的画面、关节与心跳协议；浏览器可以通过服务的局域网地址发起无线协作，控制操作校验来源和对应会话凭据，设备凭据与浏览器凭据分离。服务器内置 USB 通道仅对本机 Mac 开放；其他电脑通过本机助手使用 USB。两者共用 Python USB 传输：Mac 使用系统 usbmuxd socket，Windows 使用 Apple 设备服务的本机 TCP 27015 端口，且只选择 USB 设备，绝不回退到无线连接。助手窗口精确校验工作台来源与连接凭据，电脑端复用关节软限位、指令有效期、视角和姿态记录校验。iPad 的有线监听端口仍仅绑定回环地址。每臂 JPEG 为 960 × 600，3D 图片在同样尺寸范围内保持原始比例。

**Mac 本机 USB + 新版 iPad App** 在接受邀请后自动启用目标 **30 帧/秒**的刷新路径：手势和关节操作通过独立 USB 连接即时回传，图片复用持续连接；关节页只传 3D 画面，相机页只持续传双臂画面并定期同步关节状态。刷新由 Mac 服务驱动，浏览器每完成一帧才接受下一次刷新，不积压过期画面；支持的浏览器在 Worker 中生成 JPEG，iPad 在后台任务中准备图片后更新界面。图片尺寸与 JPEG 质量不变，手势、页面切换、关节软限位和姿态记录方式不变。需要同时更新 Mac 服务、刷新网页并更新 iPad App；未启用实时通道的新版 App、Wi-Fi 和本机助手继续使用原有约 150 毫秒一组的路径。实际帧率仍取决于工程复杂度与设备性能。协议回归运行 `npm run test:ipad:realtime`，浏览器编码回归使用 `tests/ipad_screen_encoder_ui_smoke.py`；真机性能验证使用 `tests/ipad_screen_realtime_ui_smoke.py` 配合 `testLiveScreenRealtimeUSB`，统计手势至 iPad 图片解码确认的延迟，不包括物理屏幕扫描时间。

设备 App 的安装见 [构建与部署](development.md)，协议和真机回归见 [画面协作测试](testing.md#ipad-画面协作回归)。
