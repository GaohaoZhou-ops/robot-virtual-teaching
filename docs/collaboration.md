## 两台浏览器同步作业

默认各设备独立作业：未点击同步按钮的远端不注册同步会话、不进行 3 秒轮询，也不上传示教数据。ZIP 解压、场景渲染、姿态调整和默认碰撞计算在访问设备本地完成。Mac 页面通过被动通知接收授权申请；只有申请获批后才启动双方每 3 秒的数据交换。断开或到期后立即停止该定时通讯。

1. 在运行服务的 Mac 浏览器中打开要协作的地图示教或独立示教工程，并保持页面打开。
2. 另一台设备访问该 Mac 的局域网地址，在欢迎页 `LAN :21990` 右侧点击 **同步作业 → 离线协作 → 申请离线协作**。
3. Mac 弹出授权窗口；点击 **允许同步（5 分钟）** 后，另一端自动拉取当前工程的模型、机器人、导航路径、预设和示教结果。
4. 双方每 **3 秒**交换改动，按任务、停车点和 Pose 标识合并；地图与独立对象的颜色模式、网格显示质量、路径与点位及名称显示、高程图例和标注置顶也同步更新。当前选择、机器人实时操控和视角留在各自设备。请按 SOP 分别示教不同停车点。
5. 连接后在 **同步作业 → 离线协作** 中点击 **断开链接**，欢迎页和工作台均可操作。任意一方断开、授权到期或切换工程都会停止同步，已经同步和本地示教的结果继续保存在各自浏览器中。

初次同步时，顶部同步入口和模式弹窗显示工程进度条，依次提示打包、上传、接收、解压校验、恢复与保存。上传和接收按实际传输字节更新进度；只有接收端完成恢复、首次数据交换和本地保存，并向主机确认后，两端才显示 **100% · 工程同步完成**。失败或中断不会显示完成。完成后每 3 秒的协作仍继续，但不再被当成工程传输中。

已放入地图的独立对象会保留自己的几何分组与颜色设置，例如地图使用高程色、独立对象使用原始色。接收端无需拥有原始独立示教工程，即可分别调整两者颜色；断开、刷新或再次导出工程后仍保留这些分组。

旧版本同步过的工程在升级后首次重新授权时，会重新接收一次工程资源以补齐对象分组，并合并接收端尚未同步的示教改动；之后重新授权继续复用本地资源。

工程同步完成后，可直接进入 **真机孪生** 并连接机器人，无需手动取消离线协作。连接前会等待正在进行的数据交换、同步当前改动并保存本机工程，再结束离线协作；双方已同步的工程保留。初始工程尚未完成时，真机孪生入口显示等待提示；传输完成后自动解除限制。

另一端可在离线协作面板随时点击 **重新申请授权**；待审批时也可再次点击 **申请离线协作**提交最新申请。每次批准从当时起重新计时 5 分钟。对同一工程重新授权，会合并断开期间的本地改动。同步范围是当前打开的工作区，切换模型、机器人或示教模式后需要重新授权；服务重启或页面重新打开后也需重新申请。

欢迎页 **同步作业** 旁提供 **全局重置**。警告弹窗确认后，先断开本设备的同步，再清空本设备的地图示教、独立示教及全部历史缓存、恢复副本、同步检查点、模型编辑现场与撤销记录、记住的工程保存位置，然后返回欢迎页。已导出的 ZIP / 工程目录文件、原始模型以及其他设备的结果保留；取消不会清理任何数据。

## 真机孪生

1. 在工作台加载场景和与真机匹配的机器人模型，进入 **同步作业 → 真机孪生**。
2. 勾选机器人卡片选择连接目标，支持同时连接最多 16 台机器人；默认提供 `192.168.0.112:9090`。通过 **添加机器人** 保存名称及局域网 IPv4 地址和 Web 端口，每张卡片均提供 **编辑**、**删除**，删除后可撤销。卡片及上次选择保存在当前浏览器；首次连接时填写管理员密码，再点击 **连接并同步**。连接成功后按卡片和地址分别记住密码，刷新后仍有效，之后勾选所需卡片并点击 **连接并同步** 即可批量连接，无需重复输入密码；勾选卡片本身不会发起通讯。多选时，尚未保存密码的机器人分别显示密码输入框。未成功连接的密码不会保存；网络超时、关机或本地孪生会话过期不会清除已记住的密码。只有机器人明确拒绝鉴权时才清除对应密码，重新打开弹窗要求输入，其他机器人不受影响。改名保留密码，修改地址或删除卡片会清除其密码；撤销删除同时恢复。编辑、删除及撤销卡片不会连接机器人。
3. 所选机器人都收到有效的定位和关节反馈后，弹窗对整批连接只显示一次动态对号与 **连接成功**，约 1.1 秒后自动关闭并回到工作台；动画期间短暂的数据波动不会重播。以最高约 **2 Hz** 持续读取 SLAM 定位及 20 个关节反馈，分别映射到当前地图中的多个机器人。各张卡片显示独立连接状态；某台连接失败不影响其他机器人，可重试未连接的机器人，也可点击 **进入孪生** 查看已连接的机器人。右上角按钮自动变为 **停止同步**，点击后停止所有机器人的数据通讯、关闭孪生弹窗并恢复当前虚拟示教工程的离线姿态，按钮恢复为 **同步作业**。

每台机器人共用当前工程的模型和地图，位置与关节独立更新。多机首次显示时自动调整视野。机器人本体使用不同颜色，名称和地面标记使用对应颜色；双臂末端及其下挂的第三方工具、Zivid 等设备保留原材质。着色通过独立材质实现，不修改模型文件，停止同步后恢复原来的外观。无独立本体/末端结构的单一网格不强行染色，以免改变外接设备颜色。

机器人卡片的名称、地址及端口、颜色与多选状态随 **另存为工程 / 保存工程 / 导出工程** 一起打包。加载时按地址合并并恢复选择，保留本机其他卡片，旧工程不清空本机列表；密码、鉴权令牌和实时会话不进入工程包。新设备首次连接需输入管理员密码，加载工程本身不会自动连接。

单击三维空间中任意机器人的模型或名称，右侧 **任务监控台** 切换到该机器人。也可使用监控台的 **当前机器人** 下拉框选择重叠或视野外的机器人。任务、算法列表、图像、点云及放大窗口均随机器人切换；切换时关闭上一台的本体相机，仍保持同一时刻仅一路视频流。右上角 **管理同步机器人** 可重新打开卡片弹窗调整连接，点击 **连接并同步** 后应用新的勾选范围；未勾选的已连接机器人会断开。

首版直接使用 SLAM 的 X/Y（米）与航向（弧度转换为度），保留当前虚拟底盘 Z 高度、将底盘 Roll/Pitch 置零；不匹配地图名、不做坐标标定，也不使用不同坐标系的 SDK 底盘里程计替代 SLAM。关节按真机模型元数据的 SDK 顺序映射到同名 URDF 关节，实测角度不受离线示教软限位裁剪。请使用匹配的本地机器人模型。

连接期间暂停离线回放，禁用机器人拖动；右侧完整替换为 **任务监控台**，卸载原有图谱控制台的导航、示教、相机和关节组件。任务监控台显示真机任务名称、执行状态、阶段、停车点、步骤进度、耗时和采集数量。任务完成后标为“最近任务”，无任务时明确显示空闲。

孪生模式的三维工具栏提供 **跟随视角**：从机器人后上方斜俯视，平滑跟随当前监控机器人的底盘位置及航向，观察机器人和前方局部场景。观察高度根据机器人尺寸确定，并保持高于本体；关节运动不会改变观察距离。对三维窗口进行点击、拖动、触摸、滚轮缩放、视角按键或工具栏操作时自动退出跟随，从当前观察位置继续手动操作；SpaceMouse 和共享画面的视角操作也会接管。鼠标悬停及任务监控台操作不会打断跟随。点击 **退出跟随** 恢复开启跟随前的视角；点击 **停止同步** 则恢复进入本次孪生前的工程视角，包括相机位置、观察目标、朝向和缩放。孪生期间的多机总览、手动浏览和跟随均不覆盖离线工程保存的视角。跟随只使用已有定位数据调整虚拟相机，不增加机器人通讯或发送运动指令。

只有 **当前正在跟随的机器人** 对位置、航向和关节采用 550 毫秒的显示缓冲，在已收到的相邻样本间逐帧插值，并用 80 毫秒的短窗口平滑变速、转向及晚到数据的过渡；匀速时合计约 **590 毫秒**显示延迟。跟随相机使用同一帧姿态，避免模型跳动或相机追赶。其他机器人收到新数据才更新模型，不增加插值延迟；未开启跟随时所有机器人均按这一方式更新。切换跟随对象或退出跟随后清除原缓冲。该延迟只属于画面呈现，实际数据时效还取决于机器人与网络。短暂断流停在最后有效样本，不外推运动，长时间断流或定位大幅跳变时重置历史。停止同步立即清除缓冲并恢复离线姿态与视角。顶部只保留同步操作按钮，不再交替显示同步台数和临时不可用状态；机器人卡片仍可查看具体连接情况。

任务监控独立于姿态同步，每轮读取后间隔约 1 秒继续查询。算法结果采用紧凑列表显示相机、检测位置、状态、异常类型和置信度；列表限制高度并独立滚动，较长内容悬停可查看完整说明。保留最近 24 条采集记录，演示结果保留最近 8 条并标注“演示”。只读取已有采集与算法结果，不触发拍照或算法执行。结果尚未生成、算法跳过、读取失败分别提示；切换任务时清除旧任务结果。任务数据过期或读取失败时保留上次记录并标注，不影响定位与关节继续刷新。

算法结果顶部默认显示 **最近一次 Zivid 采集**，左右图像来自同一个采集 ID，随任务的新采集自动更新，不将两次拍摄拼成一对。点击下方任意 Zivid 结果条目，可切换至该次双相机采集并标出“查看中”；手动选中的记录保持不变，新结果不会抢走画面，点击 **回到最新** 恢复自动更新。默认显示已保存的 PNG 图像，点击 **点云** 按需读取对应的 XYZ 文件，可拖动旋转、滚轮缩放、重置视角；切换条目保留图像或点云显示方式，右上角放大按钮打开双相机大窗。大窗复用已读取的数据，切换图像与点云不重复下载同一份已加载文件；切换采集、关闭页面或停止同步会释放旧数据，切换视图、收起监控台或进入后台会取消未完成的读取。文件未生成、缺失和读取失败分别提示，失败时可重试。任务进入空闲后保留正在查看的采集，新任务开始时清除选择。

放大窗口左侧提供 **已完成算法** 列表，按最新在前排列本次任务的全部已完成 Zivid 结果，不受监控台最近 24 条的限制。每条显示相机、检测位置、异常类型和红／黄状态；点击后在大窗内切换对应双相机图像或点云，保留显示方式，也可在大窗内点击 **回到最新**。打开大窗才分批读取完整索引，每批最多读取 8 条记录、同时获取两份算法元数据；已完成元数据复用缓存，只追踪未完成条目和新记录，图像与点云仅加载当前选中的采集。关闭大窗、进入后台或停止同步时取消列表读取，列表读取失败可重试。

大窗画面下方的 **采集任务** 区域显示所选记录对应的机器人、任务名称、停车点、采集动作和采集时间，并汇总左右 Zivid 的算法状态与异常类型。切换列表条目时信息随记录更新；所属作业仍可读取时，单独显示其当前状态及步骤进度，历史采集不套用其他作业的进度。图像与点云模式均保留这一区域。

算法完成且检测框非空时，监控台顶部显示检测告警，列出异常总数及涉及条目数；点击 **查看** 优先定位确定异常。每个检测框使用采集时保存的 `confidence_threshold`（缺省或无效时为 70%），`confidence` 低于该阈值时标为黄色 **疑似异常**，达到阈值则为红色异常；无有效置信度的旧记录保持红色。结果条目显示各项置信度，图像检测框与点云同步采用红、黄两色。只有疑似结果时，顶部告警、条目和相机卡片为黄色；同一条目或告警汇总中含确定异常时，整体优先红色，并注明疑似数量。演示标注不触发检测告警，算法执行或网络错误仍单独提示；旧记录的告警会标明数据已过期。

图像中每个异常框左上角显示编号、异常类型及置信度，低置信度结果额外标明“疑似”，标签颜色与检测框一致。标签在小窗和放大窗口保持可读字号；靠近图片上边缘时移至框内，靠近右边缘时向左避让，相邻标签在空间允许时自动错开，较长的类型名称省略显示并保留置信度。编号对应结果条目内的检测项。

点云中的异常区域沿用大脑 App 的处理方式：根据同次、同侧采集的 `pixel_mapping`，将检测框对应的三维点按上述置信度规则着为红色或黄色，其他点保留原色；检测框重叠时红色优先，与返回顺序无关。过滤无效深度点和预览采样时保留原始像素索引，避免着色位置偏移。算法结果或置信度更新时直接更新颜色，不重新下载点云或重置旋转、缩放视角。缺少可验证映射或尺寸不匹配时保留原色并提示；历史记录和放大窗口使用同样规则。

图像及点云只通过 `GET /api/v1/cameras/jobs/{id}/{left|right}/{png|xyzbin}` 读取已保存文件，不触发 Zivid 拍照、预览流或算法运行。采集 ID、相机侧和文件类型均由服务端校验，每个会话最多同时读取两份文件，单次读取限时 60 秒；PNG 上限 64 MiB，XYZ 上限 120,000,016 字节。点云按原生 `ABXXYZ1` 格式在 Worker 中解析，毫米转换为米、过滤无效点，每路最多显示 30 万个采样点。浏览器使用本地会话鉴权，不接收机器人 Cookie 或原生凭据。

任务监控台的 **本体相机** 提供头部左右目、胸前彩色/深度和左右手腕六路选择，未发现的相机不可开启。连接孪生后只读取列表；点击 **开启画面** 才订阅所选一路，预览沿用机器人大脑约 6 帧/秒的 JPEG 接口，显示实际预览帧率。同一时刻只显示一路，切换时先确认关闭旧订阅再开启新路；关闭画面、收起监控台、切到后台、离开工作台或停止同步都会清除画面并释放订阅。新帧在后台接收并解码完成后再替换画面，侧栏与放大窗口复用同一帧；预览区域尺寸固定，加载过程不改变布局。超过 1.5 秒没有新帧或临时读取失败时保留最后一帧，移除 LIVE 标记并叠加“画面未更新”提示，恢复后自动替换。切换相机、关闭画面或停止同步仍清除旧画面，视频异常不影响定位和任务状态。此入口不连接 Zivid 视频流、不拍照、不保存帧；其他页面占用另一台本体相机时会提示占用，不强行接管。

开启本体相机后，点击画面右上角的放大图标，可在弹窗中查看同一路实时画面。放大窗口复用已有帧和订阅；关闭按钮、Esc 或点击遮罩返回小窗，继续预览。画面关闭或停止同步时，放大窗口同时关闭。

实时显示不写入工程里的离线机器人姿态。断开、离开工作台、切换场景/机器人或刷新页面后结束姿态与任务监控连接并恢复离线显示及图谱控制台。定位或关节反馈超过 1.5 秒视为过期，保留最后有效读数并提示；服务端已计算的数据年龄不会在浏览器重复扣减。每台机器人的状态读取串行执行，正常以 500 毫秒为周期，慢响应不堆积请求；临时失败按 0.5、1、2、3 秒逐步重试，仍有效的上一帧保持原有效期，到期后才提示数据过期。网络恢复后继续读取，鉴权失效需重新连接。离线协作与真机孪生不能同时启用。

访问机器人由工作台所在电脑的服务完成，其他局域网浏览器无需直连机器人。姿态接口固定为 `GET /api/v1/slam`、`GET /api/v1/state`、`GET /api/v1/model`；任务接口仅允许 `GET /api/v1/execution/activity`、`GET /api/v1/execution`，以及带服务端校验任务 ID 和分页偏移的 `GET /api/v1/execution/captures`、`GET /api/v1/execution/demo-images`，结果详情仅允许 `GET /api/v1/cameras/jobs/{id}`、`GET /api/v1/execution/frame-captures/{id}`。空闲时只查询 activity，不启动执行组件。鉴权时额外使用 `POST /api/v1/access/login` 和只返回 Web 凭据的 `GET /api/v1/control-session`。不申请控制权，不发送使能、停止、导航、关节控制或任务执行指令。成功连接使用的管理员密码单独保存在当前浏览器的本地存储中，不写入工程文件或卡片元数据；机器人 Cookie 与会话凭据仅保留在服务端内存中，不传给浏览器。静态文件托管需同时部署本工程的 Vite 开发/预览服务才能使用此通道。

本体相机使用独立白名单：`GET /api/v1/body-cameras`、`POST /api/v1/body-cameras/preview`（只管理观看订阅）、`POST /api/v1/body-cameras/frame`（只读取预览帧）。相机 ID 限定为上述六路，不开放快照、Zivid 预览或机器人运动接口。订阅版本用于拒绝迟到请求；停止同步在中止读帧后释放原生订阅，服务端也会在约 4 秒没有读帧请求时关闭预览。

macOS 上若 Node 直连返回 `EHOSTUNREACH`，服务自动尝试系统 `/usr/bin/curl`，仍受相同接口白名单、响应大小、超时和取消约束；凭据通过进程标准输入传入，不写临时文件或命令参数。

协议及连接生命周期测试：`npm run test:robot-twin`；界面回归：在独立测试端口启动开发服务后运行 `BASE_URL=http://127.0.0.1:22061 uv run --with playwright python tests/robot_twin_ui_smoke.py`。默认仅连接本地模拟状态服务，显式传入 `--live` 才连接 `ROBOT_TWIN_ADDRESS` 指定的机器人，管理员密码通过 `ROBOT_TWIN_PASSWORD` 环境变量传入。测试读取状态并开启、切换及关闭本体相机预览，不发送运动或拍照指令；使用独立浏览器，不修改用户当前工作区。

### 没有真机时使用模拟机器人

安装项目依赖后，可在项目目录运行：

```bash
./scripts/fake_robot.mjs start
./scripts/fake_robot.mjs status
./scripts/fake_robot.mjs stop
```

`start` 在后台运行，关闭终端后继续工作，重复启动不会创建第二个进程。默认监听 `127.0.0.1:9090`，管理员密码为 `admin`。在 **真机孪生 → 添加机器人** 中保存“本地模拟机器人”卡片，地址填写 `127.0.0.1:9090`，加载场景及 `botx_abx_zivid_m70` 模型后连接。局域网浏览器连接同一工作台时也填写这个地址：机器人接口由工作台所在电脑代理访问。

服务生成沿小圆轨迹变化的 SLAM 定位、20 个关节反馈、每分钟一轮的模拟巡检任务，以及正常、确定异常、疑似异常三类算法结果。每轮先执行 40 秒，再展示完成 10 秒、空闲 10 秒。四个检测点各提供一对带 `SIMULATED ZIVID` 标记的 PNG 图像及原生格式点云：第 1 点正常，第 2 点右 Zivid 为 93% 置信度的划痕，第 3 点为 60% 的疑似划痕，第 4 点同时包含确定和疑似异常且区域部分重叠，供验证红黄标注和红色优先。本体六路相机均提供约 6 帧/秒的合成动画，画面标注 `SIMULATED CAMERA`；支持单路观看、切换、放大与关闭，不提供 Zivid 视频。所有数据均在本机生成，脚本不会访问任何真实机器人，也不实现运动控制接口。

可用 `--speed 2` 加速定位、关节及任务演示；用 `--port 9091` 启动第二台，之后 `stop` / `status` 也带上相同端口。默认仅监听本机，需要其他电脑上的工作台直连时使用 `start --host 0.0.0.0`，卡片填写模拟服务所在电脑的局域网 IPv4 地址。

测试密码变化时，先 `stop`，再运行 `FAKE_ROBOT_PASSWORD=新密码 ./scripts/fake_robot.mjs start`。已记住的旧密码会被拒绝，工作台会要求重新输入。模拟器重启也会结束旧的登录会话；可用停止和重新启动测试连接中断及重新连接。日志和进程记录位于 `.atlas-cache/fake-robot/<端口>.log`、`<端口>.pid`，不会提交到 Git。`./scripts/fake_robot.mjs --help` 显示完整用法，`npm run test:fake-robot` 验证接口和启停流程。

工作台与模拟器均启动后，可运行 `uv run --with playwright python tests/fake_robot_ui_smoke.py`，在独立浏览器中验证模型同步、跟随、任务结果、双 Zivid 图像与点云切换、异常告警、本体相机和记住密码后的重连。默认工作台为 `http://127.0.0.1:21990`，模拟器为 `127.0.0.1:9090`，可分别通过 `BASE_URL` 和 `FAKE_ROBOT_ADDRESS` 调整；此测试会先验证模拟器身份，再进行连接。

## iPad 画面协作：扫码、Wi-Fi 与数据线

在电脑上操作虚拟机器人时，可在 iPad 上查看左右臂 Zivid 2 M70 仿真画面，或拖动关节并查看与电脑同步的 3D 姿态。无需先把模型传到 iPad。

iPad 的产品定位：**配备 LiDAR 的 iPad Pro 支持本机虚拟示教与画面协作；iPad mini、iPad Air 和普通 iPad 仅支持画面协作**。画面协作不需要 LiDAR，非 LiDAR 真机默认进入“画面协作”等待页；“接收物体”和本机虚拟示教区域保留并置灰，不能打开。协作中的相机画面、关节调整、3D 视角手势和记录姿态均可使用，记录结果写入电脑工程。iPhone Pro 的 LiDAR 示教保持支持；模拟器仍保留模型预览以便开发验证。

| 电脑 | 支持的协作连接方式 |
| --- | --- |
| Windows | 扫码、Wi-Fi 配对码、数据线（本机连接助手） |
| Mac | 扫码、Wi-Fi 配对码、数据线 |

1. 更新并启动电脑服务。本机可通过 `http://127.0.0.1:21990` 打开，其他电脑通过服务器的局域网地址打开地图示教或独立示教工程，加载带左右臂末端相机的机器人。进入 **设备 → iPad / iPhone → 画面协作**。
2. iPad 打开新版 Atlas App，选择下列一种方式连接：
   - **扫码**：电脑选择 **扫码** 后自动展示二维码，可点击 **重新生成二维码** 刷新。iPad 在首页点击 **扫码配对**，App 自动识别协作用途并进入协作页面，无需先选择“画面协作”。
   - **Wi-Fi**：电脑选择 **Wi-Fi → 生成配对码**；iPad 首页选择 **画面协作**，填写电脑窗口显示的局域网地址与端口，搜索并选择服务器，输入 4 位配对码。
   - **数据线**：连接、解锁并信任电脑，保持 Atlas App 在前台。在服务器本机 Mac 使用 `localhost` 或 `127.0.0.1` 打开工作台；Windows 或通过局域网地址打开工作台的其他电脑，先按下方说明连接本机助手。**电脑发起**：选择设备后点击 **发起邀请**，在 iPad 的确认弹窗点击 **接受邀请**。**iPad 发起**：在首页“数据线连接（USB）”提示卡点击 **邀请电脑协作**，电脑当前工作台会弹出确认窗口，点击 **接受邀请** 后开始；无需先打开电脑的“画面协作”窗口。打开窗口或检测到设备不会自动发起邀请。电脑到 iPad 的有线协作不依赖 Wi-Fi，仍兼容 iPhone。
3. iPad 顶部切换 **相机画面 / 关节控制**。相机页横屏并排、竖屏上下排列；轻点画面或使用切换按钮可放大单臂，再次轻点返回双臂。
4. 关节页横屏并排显示 3D 视图与滑块，竖屏上下排列。在 **3D 姿态** 画面内，**单指拖动旋转、双指开合缩放、双指拖动平移**；双指缩放和平移可以同时进行。iPad 和电脑同步共享视角，手势不改变机器人位姿或关节值。关节面板可选择左臂、右臂、躯干等分组；角度或米数与限位来自当前机器人。拖动关节同步修改电脑的虚拟机器人，电脑调整也会回传数值与画面。轨迹播放或 Pose 记录期间暂停关节操作，仍可调整观察视角。
5. 相机页与关节页右上角均可点击 **记录姿态**，复用网页端记录流程，把当前全身关节、机器人位姿及双目 RGB/XYZ 快照保存到当前任务的停车点。关节页的记录结果显示在 **3D 姿态** 标题旁；相机页显示在画面切换控件旁。**结束协作** 位于左上角标题右侧，底部空间留给画面与关节。任务与停车点需要先在网页端新建或选择；缺少任一项时，iPad 弹窗提示对应操作。底盘偏离停车点、正在编辑姿态或播放轨迹时，也需先在网页端处理。iPad 不提供任务与停车点管理。
6. 关闭电脑协作弹窗、切换电脑窗口、桌面或浏览器标签页后仍保持连接，无需重复开始协作。浏览器暂停渲染时，iPad 保留最近画面并提示等待更新，返回工作台后自动继续。任一端结束协作、切换工程、关闭工作台或 iPad App 退出前台会停止协作。

扫码与 Wi-Fi 使用同一局域网通道，两种入口可切换并保留当前配对码。电脑可以通过网线接入路由器，iPad 使用同一网络的 Wi-Fi；多个网卡时选择 iPad 能访问的地址。Windows 启动服务时允许 Node.js 通过专用网络防火墙，并确保服务端口（默认 21990）可从局域网访问。访客 Wi-Fi、设备隔离或 VPN 可能阻止互通。配对码有效 15 分钟、仅允许一台 iPad；可点击 **更新配对码**，旧码随即失效。服务重启或协作结束后需重新配对。

其他电脑只需在浏览器打开本服务，就能为自己的当前工程生成协作二维码，**无需先同步工程或安装另一套服务**。二维码中的地址是协作连接地址，画面和关节来自发起邀请的浏览器，记录姿态也只写入该浏览器当前工程。每个协作会话使用独立配对码与凭据，多台电脑的协作互不覆盖；关闭其中一个不会中断其他会话。iPad 如需切换电脑，先结束当前协作，再扫描另一台电脑的二维码。

## Windows 数据线连接助手

**Windows 数据线协作（浏览器仍访问 Mac 服务器）**：

1. 首次使用，安装 [Python 3.9 或以上](https://www.python.org/downloads/windows/)，以及 Apple 的 **Apple 设备** App（或包含 Apple Mobile Device Support 的 iTunes）。连接 iPad、解锁并信任电脑，确认 Apple 设备 App 能识别它；参见 [Apple 官方连接说明](https://support.apple.com/zh-cn/108643)。随后在 iPad 前台打开 Atlas。
2. 工作台进入 **画面协作 → 数据线 → 下载数据线连接助手**，完整解压，在 Windows 双击 **start-windows.cmd**，保持控制台运行。无需安装整个工程，也无需安装额外 Python 包。
3. 点击 **连接本机助手**，在新窗口核对工作台地址并点击 **允许连接此工作台**。随后可从电脑点击 **发起邀请**，或从 iPad 点击 **邀请电脑协作**，由接收方在弹窗确认。浏览器拦截助手窗口时，请允许当前工作台打开弹窗后重试。
4. 返回原工作台继续使用，助手窗口可最小化，但需保持打开。关闭助手程序、助手窗口、工作台或结束协作会断开；重新打开助手后可以再次连接。Mac 远端工作台也可通过 `python3 ipadUSBBridge.py` 使用同一助手。

助手仅监听 `127.0.0.1:21994`，通过本机窗口间消息传递画面与指令，**不经 Mac 服务器中转协作画面**。工程仍留在原浏览器地址，未同步的本地工程、任务和停车点保持原位；记录 Pose 也写入原工程。访问页面、初次加载模型等仍需要能访问服务器。使用双向邀请需同时更新 iPad App、电脑服务并重新下载助手；不支持邀请确认的旧版 App 会提示更新。助手只提供协作，不提供设备文件访问、App 安装或模型传输。

## 连接状态与传输行为

有线邀请有效期为 **60 秒**。接收方可拒绝，发起方可取消；取消后对端会撤下邀请窗口，未响应或失去连接的邀请不会自动建立协作。确认前不发送画面、关节状态或控制指令。iPad 邀请由前台工作台接收，多个工作台同时接受时只允许一方建立连接；取消、拒绝和过期的邀请不能重用。扫码和 Wi-Fi 入口在欢迎页保持展开，扫描或输入配对码仍是明确的加入动作。

协作复用原有扫码器、地址输入、服务器检测和配对码控件；**接收物体** 与 **画面协作** 在首页区分，二维码自带用途，避免误触发模型接收或结果上传。App 更新可运行 `./scripts/deploy_ipad.sh`，覆盖安装保留已有项目。

画面来自当前虚拟工程，保留完整相机视野，电脑相机面板的数字缩放不改变共享画面。超过 2.5 秒未收到新画面或关节状态时提示等待更新、暂停滑块；连接保活与画面刷新独立。滑块只调整虚拟姿态，点击 **记录姿态** 才会保存 Pose。记录期间暂停关节操作和重复点击；请求重发不会重复保存，任务或停车点在记录期间切换会取消本次记录。每个关节仅保留最新指令，超过 3 秒未送达的操作会丢弃。

无线方式由 iPad 主动连接服务端 WebSocket，配对后共用有线协作的画面、关节与心跳协议；浏览器可以通过服务的局域网地址发起无线协作，控制操作校验来源和对应会话凭据，设备凭据与浏览器凭据分离。服务器内置 USB 通道仅对本机 Mac 开放；其他电脑通过本机助手使用 USB。两者共用 Python USB 传输：Mac 使用系统 usbmuxd socket，Windows 使用 Apple 设备服务的本机 TCP 27015 端口，且只选择 USB 设备，绝不回退到无线连接。助手窗口精确校验工作台来源与连接凭据，电脑端复用关节软限位、指令有效期、视角和姿态记录校验。iPad 的有线监听端口仍仅绑定回环地址。每臂 JPEG 为 960 × 600，3D 图片在同样尺寸范围内保持原始比例。

**Mac 本机 USB + 新版 iPad App** 在接受邀请后自动启用目标 **30 帧/秒**的刷新路径：手势和关节操作通过独立 USB 连接即时回传，图片复用持续连接；关节页只传 3D 画面，相机页只持续传双臂画面并定期同步关节状态。刷新由 Mac 服务驱动，浏览器每完成一帧才接受下一次刷新，不积压过期画面；支持的浏览器在 Worker 中生成 JPEG，iPad 在后台任务中准备图片后更新界面。图片尺寸与 JPEG 质量不变，手势、页面切换、关节软限位和姿态记录方式不变。需要同时更新 Mac 服务、刷新网页并更新 iPad App；未启用实时通道的新版 App、Wi-Fi 和本机助手继续使用原有约 150 毫秒一组的路径。实际帧率仍取决于工程复杂度与设备性能。协议回归运行 `npm run test:ipad:realtime`，浏览器编码回归使用 `tests/ipad_screen_encoder_ui_smoke.py`；真机性能验证使用 `tests/ipad_screen_realtime_ui_smoke.py` 配合 `testLiveScreenRealtimeUSB`，统计手势至 iPad 图片解码确认的延迟，不包括物理屏幕扫描时间。

设备 App 的安装见 [构建与部署](development.md)，协议和真机回归见 [画面协作测试](testing.md#ipad-画面协作回归)。
