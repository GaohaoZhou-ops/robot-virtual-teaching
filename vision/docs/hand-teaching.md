# 双臂手部示教

此功能用于 Vision Pro 内的虚拟机器人，记录工程示教姿态。工程必须包含 `tool_left`、`tool_right` 以及各自独立的可动关节链。双臂共同的祖先关节、底盘、躯干和头部保持当前值。

**当前状态：待 Vision Pro 真机测试。** 实际捏合识别、注视选择、跟踪中断恢复和端到端延迟尚未完成真机验收；已验证范围及未通过项见下方「验证」。

## 使用

1. 打开完整工程，完成地面对齐，进入 **1:1 沉浸游走**。如工程有未同步到空间的更改，先选择「更新空间」，关闭工程编辑窗口。
2. 在控制面板顶部选择「开启示教」，允许手部跟踪。工程包含 Zivid 光学坐标系时同时打开双相机窗口。
3. 先松开双手的拇指和食指。随后左手拇指、食指捏合控制左臂，右手捏合控制右臂；可以同时控制。握拳不作为接管手势。
4. 捏合时以当前末端位置、姿态为起点，手腕的平移和转动决定末端的相对变化。松开后立即保持最后接受的机器人姿态，再捏合从保持的位置重新接管。
5. 蓝色目标球和三轴表示期望末端位姿。不可达或移动过快时目标球变红，控制卡片及相机窗口显示原因，对应机械臂保持上一有效姿态。另一只手仍可独立操作。
6. 调整完后选择任务、停车点和可选姿态名，点击「记录当前姿态」。默认新建 `Vision 双臂示教` 任务及当前基座停车点。已有停车点必须与当前基座位置、朝向一致；选停车点不会移动机器人。
7. 记录会冻结控制，保存实际接受的全身关节值、基座位姿及左右相机的光学位姿，然后更新空间。继续示教时重新开启。未点击记录的手部调整只是当前空间姿态；重新载入或更新空间会恢复工程中保存的值。

手部离开视野、关节跟踪不完整、定位中断、异常位姿跳变或求解超时都会保持机器人。恢复跟踪后先松开再捏合，避免突然续接。操作控制卡片、相机窗口的按钮、腕部召回按钮时暂停手部控制；结束面板操作后同样先松开。相机图像本身不接管手势，可以一边观察取景一边捏合控制。示教期间禁止回放、沙盘缩放、游走和工程编辑同时改变机器人或坐标系。切换工程、退出空间或离开前台会结束手部控制。

控制面板使用分行、等宽的主要按钮，按钮之间保留 28 pt 空隙，按钮内容至少 72 pt 高并随文字大小缩放；系统按钮边框和注视高亮随点击区域一起扩大。示教期间面板集中显示任务、停车点和记录控件，退出后恢复回放、编辑等操作。任务、停车点和记录分两行排列，避免捏合选中相邻操作。

## 代码边界

所有新增代码和接线位于 `vision/`，桌面、iPad 和 `src/` 的源码保持不变。

| 位置 | 职责 |
| --- | --- |
| `AtlasVisionTeaching/VisionHandTracking.swift` | 手部授权、ARKit 更新、逐手缓存和跟踪有效性 |
| `AtlasVisionTeaching/VisionHandClutch.swift` | 可独立测试的捏合状态机、平滑、相对位姿映射和接管代次 |
| `AtlasVisionTeaching/VisionHandTeachingController.swift` | 双手调度、结果校验、可视目标、记录和生命周期 |
| `AtlasVisionTeaching/VisionHandTeachingBridge.swift` | 有超时的本机 WebKit 请求 |
| `web/handTeachingSolver.js` | 独立运动学模型、只动同侧臂、完整位姿验证、失败回退 |
| `web/handTeachingRecord.js` | 创建任务/停车点/示教姿态，检查停车点坐标 |
| `web/VisionTeachingBridge.jsx` | 接入现有文档状态和持久化，防止切换工程时写入过期结果 |
| `scripts/build_workbench.mjs` | 仅在 Vision 构建中安装适配器和文档状态更新接口 |

专用构建替换 `App.jsx` 中的 Vision 桥接组件，并在内存中的构建源码中向该组件提供现有文档状态 setter。没有修改磁盘上的共享源码。入口匹配失败会终止构建，防止重构后静默丢失功能。记录直接走现有状态更新和自动保存通道，不重新导入地图或机器人资源，不调用机器人驱动接口。调整共享 App 的桥接入口或相关状态名称后，需要运行本页的浏览器集成测试。

IK 只读复用现有求解器、软限位和关节耦合规则。准备后释放额外的视觉网格，仅保留运动学层级；每次请求都从原生空间中实际显示的关节快照开始。失败的求解可能修改计算模型，因此适配器必须完整恢复该臂，不能把最佳近似解显示成已接受的姿态。记录和重新开启不会丢失便携机器人资源。

## 调度与初始参数

| 项目 | 初始设置 |
| --- | --- |
| 捏合 / 松开阈值 | 拇指尖到食指尖 ≤ 22 mm / ≥ 35 mm，按物理空间计算 |
| 接管确认 | 连续捏合 90 ms；开启和中断恢复后必须先检测到松开 |
| 平滑 | 与采样间隔相关的一阶位置滤波 45 ms、四元数插值 65 ms |
| 目标死区 | 位置 0.7 mm、转角约 0.34° |
| 跟踪数据寿命 | 120 ms；过期数据不得继续控制 |
| 求解 | 上限 30 次/秒，最多一个在途请求；目标未变不发送 |
| 迟到结果 | 超过 150 ms、接管代次改变或松开后不应用；RPC 500 ms 超时结束控制 |
| 解的接受条件 | 完整位置误差 ≤ 4 mm、姿态误差 ≤ 1.5°，满足关节限位、耦合与冻结约束 |
| 关节变化限制 | 转动关节 180°/秒、直线关节 0.25 m/秒；超出时保持原位 |
| 相机刷新 | 示教时渲染后等待 33 ms，其他模式 100 ms；状态未变不渲染，串行执行不积压 |

这些值是初始工程参数，尚需真机测量后调优。相机间隔不是帧率保证，实际性能还取决于工程规模和设备负载。ARKit 手部数据、原生关节更新、IK 请求及虚拟相机渲染都在本机；手部示教不新增局域网的骨架或视频流。已记录的工程数据仍通过原有工程同步机制传输。

当前接受条件是运动学可达性和关节约束，**尚未新增机器人自碰撞、双臂互碰和路径连续碰撞的阻挡检查**。这版用于虚拟示教，不产生真机控制指令。Zivid 窗口是现有模型的虚拟取景，记录的是光学位姿，不会生成真实 RGB/XYZ 采集。

## 验证

从仓库根目录执行：

```bash
sh vision/Tests/check_hand_teaching.sh
node vision/Tests/check_hand_teaching_browser.mjs
```

第一组检查捏合、松开、跟踪恢复、过期结果、坐标变换、左右臂独立、不可达回退及数据格式。第二组构建专用工作台，用独立的合成双臂工程和新的浏览器上下文验证：便携机器人导入、记录、空间刷新、相机节点、重新载入和零机器人执行请求。需要 Node、完整 Xcode、`uv` 和系统 Chrome；使用本机 `21991` 测试端口，运行前关闭占用该端口的 Vision 模拟器应用。产物写入忽略的 `vision/build/hand-teaching/`。

Xcode 的 `testHandTeachingEntryAndSimulatorFallback` 接受测试运行器环境变量 `ATLAS_HAND_TEST_FILE`，指向 `vision/Tests/hand_teaching_fixture.mjs` 生成的 ZIP；检查原生入口、桥接准备、模拟器提示、回放恢复及双相机窗口。模拟器不伪造手部跟踪。

2026-10-29 验证：捏合状态机、双臂完整位姿 IK、记录/重载集成测试、原有完整工程 UI 流程、模拟器构建及未签名真机 Release 构建均通过。新增原生示教入口 UI 测试**尚未通过**：visionOS 26.5 的 XCTest 在双臂测试工程中返回 `kAXErrorIllegalArgument` 或无法取得入口的辅助功能快照，录像中入口正常显示；延迟查询也未解决。该项保留为待复验项，不以编译或浏览器测试代替原生交互验收。

真机验收需覆盖左右手及同时操作、慢移/转腕、长时间稳定保持、视野遮挡、松开时恰好返回求解结果、系统权限拒绝/撤销、在面板上捏合、工程切换、记录后重启和大工程性能。实际手指识别、系统 UI 手势仲裁和端到端延迟不能由模拟器测试代替。

ARKit 接口依据：[手部跟踪](https://developer.apple.com/documentation/arkit/handtrackingprovider)、[手部授权](https://developer.apple.com/documentation/arkit/arkitsession/authorizationtype/handtracking)、[会话运行及 provider 生命周期](https://developer.apple.com/documentation/arkit/arkitsession/run(_:))。使用逐手 `anchorUpdates` 缓存，避免多处读取会消费数据的 [`latestAnchors`](https://developer.apple.com/documentation/arkit/handtrackingprovider/latestanchors)。
